# メールのインポート

メールはすべて**インポート**ページから取り込みます。Local Emlはすでに持っているメールを見分けてスキップするので、同じものを2回インポートしても問題ありません。インポートはいつでもキャンセルできます。

![インポートページ](https://hwhang0917.github.io/local-eml/img/ja/import.webp)

## ファイルとフォルダ

次のいずれかをページにドラッグするか、クリックして選択します。

- `.eml`ファイル（1つずつでも、フォルダごとでも）
- `.eml`ファイルが入った`.zip`ファイル
- Google データエクスポート、Thunderbird、Apple Mailが書き出すような`.mbox`ファイル
- Outlookの`.pst`ファイル

どの形式で取り込んでも、メールは1通ごとに1つの`.eml`ファイルとしてライブラリに保存されます。

## 重複メール {#duplicates}

Local Emlがメールをスキップするのは、ファイルが完全に同じ場合だけです。そのため、同じメールでも2つの異なる経路から取り込むと、2回入ることがあります。経路ごとにメールの保存のされ方が少しずつ違うためです。たとえば、Google データエクスポートの`.mbox`には、IMAPにはないラベルのヘッダーが付きます。

**設定 → 重複メール**ではMessage-IDと日付でこうしたコピーを探し、余分なコピーが使っている容量を表示して、メールごとに1つだけを残します。残すコピーを自分で選ぶことも、余分なコピーを一度に削除することもできます。一度に削除した場合は、最も古いインポートが残ります。どのコピーに対して行った操作（スター、既読状態、カテゴリ）も、残るコピーに引き継がれます。

## IMAPメールボックス

IMAPは、メールアプリがサーバー上のメールボックスを読むための標準的な方式です。サーバーのアドレス（ホスト）、ポート、ユーザー名、パスワード、フォルダを入力します。ほとんどのプロバイダーは暗号化（TLS）されたポート993を使います。ポート143も使え、その場合はSTARTTLSで暗号化に切り替わります。フォルダは変更しない限り`INBOX`です。

Local Emlは読み取るだけです。コピーをダウンロードするだけで、サーバー上のメールを移動したり、既読にしたり、削除したりすることはありません。

接続情報を**プロファイル**として保存しておけば、次回から入力し直す必要がありません。保存したプロファイルはIMAPタブの上部にカードとして並び、カードをクリックするとフォームに入力されます。パスワードは保存されないので、毎回入力します。唯一の例外は、カードのスイッチでそのプロファイルのバックグラウンド同期をオンにした場合です。[新着メールの受信](./sync)を参照してください。

## S3バケット

バケット内のプレフィックスの下にある`.eml`ファイルをすべて取り込みます。バケット、リージョン、プレフィックス（任意）、アクセスキーID、シークレットキーを入力します。両方のキーを空欄にすると、このコンピューターですでに設定されている認証情報（`~/.aws/credentials`または`AWS_*`環境変数）が使われます。シークレットキーとセッショントークンは保存されないので、毎回入力します。

### MinIO、Cloudflare R2、Backblaze B2など

S3ストレージを提供しているのはAmazonだけではありません。MinIO、Cloudflare R2、Backblaze B2、Wasabi、そして多くの家庭用NASも同じ仕組みで動くので、Local Emlから使えます。

**S3互換サービス**欄の**エンドポイントURL**に、サービスのアドレスを入力します。たとえばR2なら`https://<アカウントID>.r2.cloudflarestorage.com`、自宅のネットワークにあるMinIOサーバーなら`http://nas.local:9000`のような形です。AWSを使う場合は空欄のままにします。

MinIOや自分で運用しているサーバーでは、**パス形式のアドレス指定**もオンにしてください。バケット名をアドレスのどこに入れるかが変わり、`mail.nas.local:9000`ではなく`nas.local:9000/mail`に接続します。自分で運用しているサーバーで「バケットが見つからない」と表示されたり接続できなかったりする場合は、たいていこのスイッチで解決します。リージョンを空欄にすると`us-east-1`が使われます。こうしたサービスの多くはこの値を前提にしています。

### 保存したプロファイル

シークレットキー以外はプロファイルとして保存できます。保存したプロファイルは**インポート**ページと**エクスポート**ページの両方でフォームの上にカードとして表示されるので、1つのプロファイルを両方で使えます。カードには、バケット、プレフィックス、リージョンまたはエンドポイント、そして保存したアクセスキーIDを使うのか、コンピューターの認証情報を使うのかが表示されます。カードをクリックしてフォームに入力したら、あとはシークレットキーを入力するだけです。

プロファイルを削除しても、消えるのは保存した接続情報だけです。バケットの中身には触れません。

## エクスポート

**エクスポート**ページではライブラリ全体を1つの`.zip`ファイルとして保存するか、S3バケット（AWS、または上記のS3互換サービス）にアップロードできます。すでにバケットにあるファイルはスキップされるので、同じエクスポートをもう一度実行しても安全です。

検索結果など、一部のメールだけをエクスポートするには、ライブラリのエクスポートボタンを使います。[検索結果のエクスポート](./search#exporting-search-results)を参照してください。

`.zip`にはデータベースのコピーも含まれます（保存したパスワードは除かれます）。新しいコンピューターなどで、その中の`.eml`ファイルをインポートしたあと**設定 → バックアップから復元**を使うと、スター、カテゴリ、設定、プロファイルが元に戻ります。

## 自動バックアップ

アーカイブしたあとでメールボックスからメールを削除した場合、Local Emlにあるものが唯一のコピーかもしれません。**エクスポート**ページの下部にある**自動バックアップ**は、決まった間隔でライブラリをフォルダにコピーします。ディスクが1台壊れても、メールを失わずに済みます。

1. 外付けドライブ、NAS、またはDropbox・OneDrive・Google Driveが同期するフォルダのフルパスを入力します。たとえば`E:\Mail Backup`や`/Volumes/Backup/Mail`です。フォルダが存在しない場合は、Local Emlが作成します。
2. **毎日**または**毎週**を選び、**保存**をクリックします。**今すぐバックアップ**をクリックすると、すぐに1回実行されます。

バックアップは、Local Emlが動いている間に実行されます。バックグラウンドサービスとしてインストールした場合は常時、そうでない場合はウィンドウを開いている間です。閉じている間に予定されていたバックアップは、次に起動してから数分後に実行されます。最初のバックアップではすべてがコピーされます。それ以降は新しいメールだけがコピーされるので、通常は数秒で終わります。バックアップ先のフォルダから何かが削除されることはないので、Local Emlで削除したメールもバックアップには残ります。ドライブが接続されていない場合などにバックアップが失敗すると、カードにその理由と最後に成功したバックアップの日時が表示され、Local Emlは1時間後にもう一度試します。

フォルダには、メール1通につき1つの`.eml`ファイルが入った`emails`フォルダと、スター、カテゴリ、設定、プロファイル（パスワードを除く）が入った`local-eml.db`があります。新しいコンピューターで復元するには、`emails`フォルダを**インポート**ページにドロップしてから、**設定 → バックアップから復元**で`local-eml.db`を選びます。
