# 개인정보와 데이터

## 데이터는 어디에 있나요

모든 데이터는 폴더 하나에 있습니다. Linux와 macOS에서는 `~/.local-eml/`, Windows에서는 `%USERPROFILE%\.local-eml\`입니다.

| 경로 | 내용 |
|---|---|
| `eml/` | 내용 해시로 이름 붙인 `.eml` 파일 그대로의 메일 |
| `db/local-eml.db` | SQLite 데이터베이스: 메타데이터, 검색 색인, 프로필, 설정 |
| `logs/local-eml.log` | 애플리케이션 로그. 제목과 주소가 포함됩니다 |
| `keys/secret.key` | 저장된 IMAP 비밀번호를 암호화하는 키 |
| `prefs.json` | 실행 설정. 현재는 임시 세션 스위치만 있습니다 |

폴더와 그 안의 모든 파일은 같은 PC의 다른 사용자가 접근할 수 없는 권한으로 만들어집니다.

## 네트워크

Local Eml은 `127.0.0.1`에서만 듣습니다. 네트워크에서 접근할 수 없고, 다른 웹사이트에서 오는 요청은 거부합니다. 바깥으로 나가는 연결은 사용자가 요청한 것만 있습니다. IMAP·S3 가져오기와 내보내기, 그리고 **설정 → 정보**의 업데이트 확인입니다.

## 자격 증명

- **S3 Secret Key와 세션 토큰**은 저장하지 않습니다.
- **IMAP 비밀번호**는 프로필의 백그라운드 동기화를 켜지 않는 한 저장하지 않습니다. 켜면 암호화해 보관하며, 자세한 내용은 [새 메일 받기](./sync#비밀번호는-어떻게-되나요)를 보세요.
- 호스트명, 버킷명, 사용자명, Access Key ID는 비밀이 아니므로 그대로 저장합니다.

## 임시 세션

`.eml` 폴더를 잠깐 열어 검색만 하고 흔적을 남기고 싶지 않을 때 쓰는 기능입니다.

**설정 → 개인정보 → 더블클릭 실행을 임시 세션으로**를 켜세요. 다음 실행부터 더블클릭할 때마다 시스템 임시 디렉터리 안의 임시 폴더에서 빈 라이브러리로 시작하고, 앱을 닫으면 그 폴더가 삭제됩니다. 앱이 비정상 종료되면 남은 파일은 다음 실행 때 지워집니다. 임시 세션 중에는 페이지 상단에 배너가 표시됩니다.

디스크에 남는 것은 이 스위치를 기억하는 `prefs.json` 하나뿐이며, 메일이나 자격 증명은 들어 있지 않습니다.

백그라운드 서비스가 실행 중이면 이 스위치는 쓸 수 없습니다. 서비스는 닫히지 않기 때문입니다. 그런 PC에서는 서비스를 멈추거나, `--ephemeral` 옵션 또는 `LOCAL_EML_EPHEMERAL=1`로 실행하세요. 서비스의 라이브러리는 건드리지 않는 임시 세션이 열립니다.

## 모든 데이터 삭제

**설정 → 개인정보 → 지금 모든 데이터 삭제**는 모든 메일, 검색 색인, 가져오기 기록, 로그를 지우고, 라이브러리가 다시 채워지지 않도록 백그라운드 동기화를 끕니다. 비밀번호를 제외한 저장된 프로필, 카테고리, 설정, 암호화 키는 남습니다. 실행 전에 확인 단어를 입력해야 합니다.

::: warning 보증하지 않습니다
임시 세션과 모든 데이터 삭제는 파일을 직접 지우는 것과 같은 일반적인 방식으로 삭제합니다. 편의 기능일 뿐 안전한 완전 삭제가 아닙니다. Local Eml은 삭제한 데이터를 복구할 수 없다고 보증하지 않으며, SSD나 저널링 파일 시스템에서는 복구되는 경우가 많습니다. 또한 Local Eml은 삭제한 데이터를 되살릴 수 없으니, 필요한 데이터는 따로 백업해 두세요. Local Eml의 다른 기능과 마찬가지로 이 기능들은 [GPL v3](https://github.com/hwhang0917/local-eml/blob/main/LICENSE)에 따라 어떠한 보증도 없이 있는 그대로 제공됩니다.
:::
